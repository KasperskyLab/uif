# @kaspersky/hexa-ui — оптимизация бандла: отчёт

**Суть в одной строке:** самый частый путь импорта (`Button` и типовой набор компонентов) стал
на **25–30% легче** в стартовом бандле, без изменения поведения и с зелёной тест-сьютой; экономия
зафиксирована перф-бюджетом в сборке, чтобы не откатилась.

---

## 1. Какие улучшения увидит пользователь

- Экраны с формами, полями и кнопками **быстрее становятся интерактивными**: в стартовой загрузке
  на ~64 КБ меньше JS и на ~150 мс меньше работы по разбору кода, плюс ~1.4 МБ меньше памяти на
  первом рендере. Тяжёлый движок разметки подсказок (markdown) теперь подгружается **только если
  пользователь реально открыл markdown-подсказку**, а не у всех заранее.
- Видимое поведение не изменилось: те же компоненты, те же подсказки, тот же внешний вид.
- Побочно починен баг сборки, из-за которого компонент `Toolbar` мог не собираться у части
  потребителей — то есть меньше «сломанных» экранов на проде.

## 2. Какие объективные метрики улучшены

Размер того, что тянет потребитель при импорте (published `esm/`, минификация, gzip, react внешний):

| Импорт | Было | Стало | Δ |
|---|---|---|---|
| `Button` | 216.7 КБ gz | **152.3 КБ gz** | **−30%** |
| Button + Textbox + Checkbox + Modal + Tooltip | 263.1 КБ gz | **198.4 КБ gz** | **−25%** |
| `Table` | 800.5 КБ gz | 729.5 КБ gz | −9% |
| Вся библиотека | 1330.1 КБ gz | 1258.2 КБ gz | −5% |

Рантайм первого рендера (изолированный замер): отложено **≈1.44 МБ heap + ~150 мс parse**
(движок markdown больше не инициализируется на старте).
Регресс-контроль: `tsc` чисто, полная jest-сьюта **87/88 сьютов, 971 тест зелёные**
(единственный падающий тест — предсуществующий, к этим правкам не относится, проверено откатом).

## 3. Как это сказывается на разработке (RnD) — и за счёт чего достигнуто

**Влияние на RnD:**
- Появился **измеримый перф-бюджет**: `npm run build` прогоняет `perf/bench.mjs --check` и **падает
  при регрессе размера >2%**. Экономия защищена от случайного отката, размер бандла стал
  контролируемой метрикой, а не «как получилось».
- В пакете есть **диагностический инструмент** (`bench.mjs analyze/trace`): за минуты видно, какой
  компонент/зависимость раздувает бандл и по какой цепочке импортов — раньше это было неочевидно.
- Зафиксирован **приоритезированный план** дальнейших шагов (`perf/TODO.md`) с оценкой выигрыша,
  включая самый крупный остаток.

**За счёт чего достигнуто:**
- Корневая причина — не конфиг сборки (tree-shaking работает), а **связанность компонентов в коде**:
  `Button → Dropdown → Toggle → FormLabel → Markdown` затягивал движок markdown (markdown-it + dompurify,
  ~170 КБ) в каждую кнопку. Разорвали цепочку: `FormLabel` грузит `Markdown` лениво (`React.lazy`) —
  он уходит в отдельный async-чанк по требованию.
- Плюс точечный багфикс нерезолвимого алиаса в стилях `Toolbar`.

**Чего НЕ дала эта итерация (честно):** основной «пол» размера — это фиксированные косты в каждом
компоненте: цвета из `@kaspersky/hexa-ui-core` (~189 КБ) и базовый рантайм antd v4 (~48 КБ gz). Они
архитектурные/кросс-пакетные; самый крупный из них (цвета, больше текущего выигрыша) вынесен в
`perf/TODO.md` как следующий шаг и требует кросс-командного решения.
