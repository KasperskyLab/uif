# Принципы написания документации (feature-docs)

Как писать docs-страницы для компонентов (эталон — [`RowSelectionDocs.md`](./RowSelectionDocs.md),
[`DataSourceFunctionDocs.md`](./DataSourceFunctionDocs.md)). Цель — документация **для людей**, а не сухой
перечень пропов.

## Главное правило
Пиши от **задачи пользователя**, а не от API. Читатель приходит с вопросом «как мне сделать X», а не «какие
есть поля у пропа Y». Сначала — зачем фича и когда её брать, потом — как ею пользоваться.

## Принципы

1. **Feature-driven, не API-reference.** Разделы — это сценарии использования («Базовый пример»,
   «Обновление данных», «Предвыбранные строки»), а не список свойств. Таблица пропов — максимум как
   вспомогательная сводка внутри раздела.
2. **Начинай с базового примера.** Самый частый кейс — в самом верху, с рабочим кодом. Читатель должен
   скопировать и поехать.
3. **Код — продуктовый и минимальный.** Реальные имена (`SomeProductTable`, `ProductRow`), только то, что
   относится к теме. Комментарии в коде поясняют **неочевидное** (а не «здесь мы вызываем функцию»).
4. **Объясняй «почему», а не только «что».** Контекст, стратегии, последствия выбора. Пример: не «`isSelectedAll`
   — булев флаг», а «`isSelectedAll: true` — сигнал перейти на стратегию exclude ("выбраны все, кроме…")».
5. **Ссылайся на Storybook** для каждого нетривиального сценария:
   `> **Пример в Storybook:** [Название](./?path=/story/hexa-ui-components-table-<раздел>--<стори>)`.
6. **Показывай связь с другими фичами** и ссылайся между доками (выбор строк ↔ серверная пагинация и т. п.).
7. **NB-блоки для важного.** Всё, что легко забыть или сломать, выделяй:
   `> **NB!** ...`. Подводные камни — отдельным разделом в конце, человеческим языком, нумерованным списком.
8. **Структура заголовков:** `###` — раздел фичи, `####` — подтема, `#####`/`######` — частные случаи.
9. **Тон — доброжелательный и живой.** Без канцелярита и переусложнённых формулировок. Пиши так, как объяснял
   бы коллеге.

## Чек-лист перед сдачей
- [ ] Есть базовый пример с рабочим кодом в начале.
- [ ] Для каждого сценария — ссылка на Storybook.
- [ ] Объяснено «когда и зачем», а не только «как».
- [ ] Важные грабли вынесены в NB / раздел «Подводные камни».
- [ ] Код читается как продуктовый, комментарии — только про неочевидное.
- [ ] Файл лежит в `stories/docs/*Docs.md` и подключён в стори через `withMeta(MetaData, XxxDocs)`.
