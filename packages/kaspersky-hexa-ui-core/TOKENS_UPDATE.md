# Обновление токенов цветов из Pixso

Токены цветов живут в двух сгенерированных файлах — `src/colors/tokens/tokens.css` (для SSR) и
`src/colors/tokens/tokens.ts` (инжектируется в `<head>` при импорте `colors/css`). Оба файла обновляются
одним скриптом из CSS-файлов, которые экспортирует Pixso.

## Для дизайнеров

### Один раз перед первым обновлением

1. Установить зависимости в пакете компонентов `@kaspersky/hexa-ui`: `npm i`.
2. Установить зависимости в этом пакете: `npm i`.
3. Создать файл `.env` по образцу `.env.example` (нужен только для просмотра результата в сторибуке).

### Каждое обновление

1. В Pixso экспортировать переменные в формате CSS из файлов, в которых были изменения. Pixso отдает файл
   `variables.css` — его нужно переименовать строго по таблице. Других имен быть не должно: скрипт
   остановится с ошибкой.

   | Файл в Pixso                    | Имя файла в пакете |
   |---------------------------------|--------------------|
   | [B2B] Hexa-UI Core              | `core.css`         |
   | [B2B] Hexa-UI Widget            | `widgets.css`      |
   | [B2B] Hexa-UI Static Tokens     | `static.css`       |
   | [B2B] Hexa-UI Semantic Tokens   | `semantic.css`     |

2. Положить измененные файлы в папку `src/colors/pixso/`, заменив лежащие там файлы.

3. Посмотреть, что изменится, ничего не записывая:

   ```shell
   npm run check-tokens-change
   ```

   Скрипт выведет количество прочитанных токенов по каждому файлу и список изменений:
   `~` — токен получит новое значение (старое `->` новое), `+` — токен будет добавлен.

4. Применить изменения:

   ```shell
   npm run update-colors
   ```

5. Проверить результат в сторибуке (команда собирает пакет, копирует его в `@kaspersky/hexa-ui`
   и запускает сторибук):

   ```shell
   npm run storybook-hexa-ui
   ```

6. Создать PR. В нем должны быть изменения `src/colors/tokens/tokens.css`,
   `src/colors/tokens/tokens.ts` и загруженные файлы из `src/colors/pixso/`.

## Для разработчиков

Скрипт — `src/colors/pixso-build.js`, тесты — `src/colors/pixso-build.test.js`. Команды:

| Команда                       | Что делает                                                                 |
|-------------------------------|----------------------------------------------------------------------------|
| `npm run check-tokens-change` | Читает `src/colors/pixso/*.css`, печатает отчет, файлы не меняет           |
| `npm run update-colors`       | То же, но записывает `tokens.css` и `tokens.ts`                            |
| `npm run storybook-hexa-ui`   | `update-colors` + `release` + сторибук в соседнем `@kaspersky/hexa-ui`     |

### Как читается экспорт Pixso

Pixso экспортирует переменные блоками `:root { ... }` и `:root[<коллекция>="<режим>"] { ... }`.
Режим по умолчанию первой коллекции файла Pixso выводит голым `:root`, без атрибута.

| Блок в экспорте Pixso                                         | Куда попадают токены                                             |
|---------------------------------------------------------------|------------------------------------------------------------------|
| `:root[...="... Light"]`                                      | `:root,`<br>`.theme-light,`<br>`.hexa-ui-light-theme { }`         |
| `:root[...="... Dark"]`                                       | `.theme-dark,`<br>`.hexa-ui-dark-theme { }`                       |
| `:root[staticColors="..."]` — статическая палитра             | `:root { }`, имя `--color--<имя цвета>`                            |
| `:root[...="Tablet"]`, `:root[...="Mobile"]`                  | `@media (<tablet breakpoint>) { :root { } }`, `@media (<mobile breakpoint>) { :root { } }` |
| `:root[...="Desktop"]` и любой другой режим без темы          | `:root { }` — значения по умолчанию                               |
| голый `:root`, если в файле есть блок `Dark` с теми же токенами | светлая тема (так устроен экспорт `widgets.css`)                |
| голый `:root` в остальных случаях                             | `:root { }` — значения по умолчанию                               |


В режимах геометрии Desktop — это значение по умолчанию в `:root`,
а Tablet и Mobile перезаписывают тот же токен внутри медиазапроса:

```css
:root {
  --geometry--gap--closest: var(--s50);
}

@media (min-width: 768px) and (max-width: 1023px) {
  :root {
    --geometry--gap--closest: var(--s50);
  }
}

@media (max-width: 767px) {
  :root {
    --geometry--gap--closest: var(--s50);
  }
}
```

### Имена токенов

Pixso разделяет уровни имени одной чертой, в пакете принято две. Преобразование механическое:

| В Pixso                                       | В пакете                                           |
|-----------------------------------------------|----------------------------------------------------|
| `--fg-neutral-primary`                        | `--fg--neutral--primary`                           |
| `--Background-global`                         | `--background--global` (нижний регистр)            |
| `--section message-collapsed-max_height`      | `--section_message--collapsed--max_height` (пробел → `_`) |
| `--gap-closest` в режиме `Tablet`             | `--geometry--gap--closest` внутри `@media (<tablet breakpoint>) { :root { } }` |
| `--neutral-neutral_0` из коллекции `staticColors` | `--color--neutral_0`                           |

### Ограничения

* Переименованный в Pixso токен — это новый токен. Старый остается в пакете; перенести его в секцию
  deprecated можно только руками.
* Скрипт не обновляет JS-объекты в `src/colors/js/index.ts` (`colors`, `productColors`, `widgetColors` и т.д.)
  и файлы компонентов `src/colors/css/*.ts`. Они остаются такими, какими были сгенерированы ранее.
* Если один и тот же токен в одной теме встречается в экспорте с разными значениями, скрипт останавливается с ошибкой.
